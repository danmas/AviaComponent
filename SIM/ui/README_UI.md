# Экран цеха — модель Предприятия

Первый срез этапа 4. Показывает физическую реальность: где стоят партии, что ждёт в очереди, какой ресурс простаивает и что изменилось за смену.

Экран читает **только** срез `shop` через пакет `api-client`. Правила цеха, ёмкости и очередь он не считает — они в ядре.

## Запуск

Три способа, все из каталога `SIM`:

```bash
# 1. разработка: сервер с источниками Vite (без этого браузер получит отказ CORS)
npm run api:ui
cd ui && npm run dev          # http://127.0.0.1:5173/

# 2. собранный экран и API на одном порту (без Vite и без CORS)
cd ui && npx vite build && cd ..
npm run api:dist              # http://127.0.0.1:3477/
```

В сборке адрес API берётся из адреса страницы: экран и API живут на одном хосте. В разработке порты разные, поэтому сервер `api:ui` перечисляет источники явно.

Порты: сервер 3400 (`api`/`api:ui`), 3477 (`api:dist`), приложение 5173. Все закреплены: занятый порт даёт внятную ошибку, а не тихий сдвиг.

## Параметры адреса

Одна ссылка — одно состояние. Это нужно, чтобы снимок экрана был воспроизводим.

| Параметр | Значения | По умолчанию |
|---|---|---|
| `shift` | 0…11 | 0 |
| `mode` | `now`, `movement` | `now` |
| `overlay` | `none`, `urgent`, `breakdown`, `scrap`, `incoming` | `none` |
| `level` | `clean`, `late`, `paper`, `empty` | `clean` |
| `seed` | целое больше нуля | 42 |

Примеры:

- `?shift=0` — начало партии, очереди пусты
- `?shift=3&mode=movement` — что изменилось между сменами 2 и 3
- `?shift=1&overlay=breakdown` — простой ресурса с причиной
- `?shift=2&level=empty` — пустые поля: у части партий нет материала и КД
- `?shift=8` — поздняя стадия, большинство партий прошло маршрут
- `?shift=3&overlay=incoming` — до поступления `order-5`: панели неразобранных нет
- `?shift=4&overlay=incoming` — заказ поступил и висит неразобранным, партии `batch-7` в цехе нет

## Что показывает

**Шапка:** смена, минута, уровень, помеха, seed.

**Счётчики:** сколько операций не готово, ждёт, в работе, закрыто.

**Маршрут** — 7 участков в порядке прогона: Токарная ЧПУ → Фрезерная → Термообработка → Слесарная → Испытательная → Окончательный контроль → Склад ГП. У каждого участка: тип ресурса, работающая операция с ресурсом, очередь с числом, закрытые. Свободный участок показан штриховкой и подписью «свободен», а не скрыт с маршрута.

**Садка** — у печи строка из среза: «садка: занято 8 из 8 · batch-1, batch-4» или со свободным местом «занято 4 из 8 · свободно 4». Считается из `chargePieces` ресурса и работающих операций. Станки и люди этой строки не имеют.

**Частичное выполнение** — счёт операции «сделано N из M, годное K». Годное — сделанное минус брак. План на той же строке, отдельно.

**Простой** — рамка с причиной и промежутком: `простой: поломка · 0→720`. Открытый простой (`until: null`) показывается как «сейчас», а не как законченный.

**Неразобранные заказы** — список из среза ролей, только записи `kind = order` со статусом `unparsed`. У строки идентификатор, договорный срок и две кнопки: «принять» и «отложить». После решения экран заново читает цех и роли текущей смены: принятый заказ уходит из списка, его партия появляется в таблице. Покрытие на этом экране не показывается.

**Партии по маршруту** — таблица: сколько штук, сколько шагов пройдено, где стоит сейчас, **сколько пролежала**, почему не готова («нет материала», «нет конструкторской документации», «не закончена предыдущая операция»). Колонка «появление»: у партии с `appearedAt > 0` стоит «новая · N мин», у стартовой (`appearedAt` равен нулю) ячейка пустая.

**Схема маршрута** — участки связаны в порядке движения. На связи стоит число операций участка-источника, готовых к запуску: это же число показано в очереди участка, второго правила подсчёта нет.

**Узкое место** — участок с наибольшей суммой пролёживания ожидающих операций. При равенстве суммы — с большим числом ожидающих, при полном равенстве — раньше в маршруте. Место помечено рамкой, а не цветом: цвет на экране отвечает за достоверность, не за оценку. После совместной садки печь держит очередь на сменах 1–3. На смене 4 узкое место — слесарная. К смене 10 очередь пуста, узкого места нет.

**Пролёживание** — три состояния, которые нельзя склеивать: «ещё не готова» (ждать нечего), «лежит N мин» (ожидание идёт), «пролежала N мин» (ожидание закончилось и не растёт). Считается из моментов `readyAt` и `startedAt` среза, а не из статуса.

**Движение** (режим `movement`) — таблица изменений между прошлой и текущей сменой: партия, участок, было, стало, счёт. Строится из двух реально запрошенных срезов.

## Язык

Бланк первичного учёта, не дашборд. Экран показывает записи, а не измерение.

- **Плотность линии несёт достоверность.** Работающая операция — полная тушь, ожидающая — пунктир, закрытая — выцветшая.
- **Цвет не несёт оценки.** Красного и зелёного нет: оценка принадлежит игроку, а не оформлению.
- **Ноль и «нет данных» различимы.** `null` — прочерк с подписью, `0` — ноль.

```bash
cd ui

npm run check     # tsc + запрет обращений мимо api-client
```

Проверка границы запрещает в `SIM/ui/`:

- импорт из `plant/`, `system/`, `contract/`, `api/`
- библиотеки `fastify`, `@fastify/*`, `ws`
- собственные `fetch(`, `new WebSocket(`, `XMLHttpRequest`

Тесты — исключение: им нужен реальный сервер, а не мок.

## Чего этот экран не делает

- Не показывает показатели Системы: четыре показателя, покрытие и реестр достоверности — это свод, отдельный экран.
- Принимает только два решения по неразобранному заказу: «принять» и «отложить». Других решений руководителя на этом экране нет.
- Не показывает рабочие места ролей. Из среза ролей берётся только список неразобранных заказов.
- Не считает мощность, очередь и длительности: всё приходит из среза.
