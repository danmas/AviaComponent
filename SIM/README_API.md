# HTTP-сервер сессий

Сервер раздаёт прогон стенда. Правила цеха, ёмкости и порядок очереди остаются в ядре: обработчик вызывает `runStand` и отдаёт срез.

Запуск из каталога `SIM`:

```bash
npm run api
```

Порт по умолчанию — **3400**, только `127.0.0.1`. Другой порт задаётся переменной `SIM_API_PORT`. Если порт занят, процесс пишет причину и завершается с ненулевым кодом.

Перезапуск процесса стирает сессии из памяти. В ответе сессии стоит `replayable: true`: те же seed, уровень, помеха, горизонт и решения в том же порядке смен дают тот же срез.

## Версия контракта

Версия идёт **префиксом пути**: `/v1/...`. Она же дублируется полем `apiVersion` в теле каждого ответа, включая отказы: ответ может быть сохранён в файл или лог, где путь уже потерян.

Обращение к неизвестной версии (`/v2/...`) даёт `404` с телом `{ "apiVersion": "v1", "error": "unknown-api-version", "supported": ["v1"] }`. Это `404`, а не `400`: запрос адресован другой версии, а не содержит ошибку в теле. Путь без версии (`/sessions`) не обслуживается — тоже `404`.

## Маршруты

Все маршруты — под `/v1`.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/v1/sessions` | Создать сессию. Тело: `seed`, `level`, `overlay`, необязательный `horizonShifts` |
| `GET` | `/v1/sessions/:id` | Метаданные и срез свода текущей смены. `?shift=N` — уже выданный срез смены N |
| `GET` | `/v1/sessions/:id/shop` | Срез цеха, слой `shop` |
| `GET` | `/v1/sessions/:id/roles` | Записи ролей, слой `roles` |
| `GET` | `/v1/sessions/:id/trace` | След прогона: события движения и кадры выданных смен |
| `POST` | `/v1/sessions/:id/decisions` | Принять решение |
| `POST` | `/v1/sessions/:id/advance` | Шаг на следующую смену |
| `GET` | `/v1/sessions/:id/stream` | WebSocket: события сессии. Шаг — сообщение `{ "type": "advance" }` |

Уровни: `clean`, `late`, `paper`, `empty`. Помехи: `none`, `urgent`, `breakdown`, `scrap`.

Горизонт сессии — целое число от 10 до 15 смен. Вне диапазона сервер отвечает `400` и называет диапазон. Если поле опущено, берётся горизонт стенда (12) и возвращается в ответе.

Смена 0 выдаётся при создании. `advance` увеличивает текущую смену на одну и считает срез прогоном с горизонтом «номер смены + 1». На последней смене горизонта приходит событие `session-finished`. Дальше шаг отклоняется.

## Срезы

`GET /sessions/:id` отдаёт свод: четыре показателя, покрытие каждого и реестр достоверности. Реестр — те же покрытия, отдельной формулы нет. Мощность участка копируется из записи загрузки прогона вместе со своей единицей. Участков загрузки шесть: склад ГП в этот список не входит.

Срез цеха есть только у `GET /sessions/:id/shop`. В метаданных сессии и в записях ролей нет состояния станков.

`GET /sessions/:id/trace` отдаёт след уже сыгранных смен: шапку, события и кадры. Кадр — не срез цеха. Формат и замер — в `README_SIM_DATA.md`, раздел «След прогона».

Уже выданный срез хранится в журнале сессии. Решение, принятое после выдачи, его не переписывает.

## Формат решения

```json
{ "type": "priority", "batchId": "batch-3", "rank": 0 }
```

`type` — вид решения, `batchId` — партия, `rank` — целое число: меньше значит раньше в очереди. Момент применения ставит сервер: начало текущей смены. Поле `appliedAt` в прошлом даёт `409`, сессия не меняется. Неизвестный `type` даёт `400` и список допустимых типов.

Повтор по той же партии допустим. Новый ранг действует с текущего момента, прошлые срезы остаются как были выданы.

В журнале решения видны момент, действие, показатель «риск сроков» на момент решения, его покрытие и последствие.

## События

Сообщение WebSocket: `{ "apiVersion", "seq", "at", "type", "payload" }`. `seq` растёт в пределах сессии.

Реестр типов закрыт пятью значениями: `shift-started`, `shift-completed`, `metrics-updated`, `decision-applied`, `session-finished`. Клиент обязан игнорировать тип, которого нет в его версии: так сервер новее клиента не ломает чтение потока.

Журнал сессии хранит последние **200** записей. Клиент, который переподключается, передаёт `?lastSeq=` — номер последнего полученного события, и получает только события с большим номером. Если `lastSeq` старше окна, приходит `{ "error": "journal-window-exceeded", "oldestSeq" }` и клиент перечитывает срез с нуля: восстановление есть, потери нет.

Шаг по HTTP возвращает те же события в теле ответа.

## CORS

Источники задаются переменной `SIM_API_ORIGINS` — список через запятую, например `http://127.0.0.1:5173`. Пустое значение выключает CORS: проходят запросы без `Origin` (curl, тесты, сервер-сервер).

Значение `*` отвергается при старте: процесс пишет причину и завершается с кодом 1. Источник не из списка разрешающего заголовка не получает.

## Серверный код без enum

В `SIM/api/` запрещены `enum`, `namespace` и параметр-декораторы: Node в strip-only режиме их не поддерживает. Сервер живёт на `as const` и union-типах, как ядро. Нарушение ловит `node --experimental-strip-types contract/boundary.ts` — файл с `enum` в зоне `api` даёт код 1.

## Описание API и клиентские типы

```bash
npm run openapi     # api/openapi.json — из фактических ответов сервера
npm run api-client  # api-client/types.ts — из openapi.json
```

`api/openapi.json` помечен `x_generated: true`. Ручная правка запрещена: тест `test/openapi.test.ts` сверяет схемы с ответами сервера и падает на любом расхождении — лишнее поле в ответе, пропавшее обязательное поле, убранный маршрут.

Типы клиента генерируются из описания, руками не пишутся. Клиент живёт в `api-client/client.ts`: у него нет зависимостей от React, DOM и `fastify`, транспорт передаётся снаружи (`createClient({ baseUrl, transport })`), поэтому один и тот же клиент работает в браузере и в Node.

**Ограничение вывода схем.** Схемы выводятся по фактическим значениям на стенде `clean`/`none`, seed 42. Поле, значение которого на этом прогоне ни разу не встретилось, опишется уже (например `load: number` вместо `number | null`). Покрыты все поля, реально встречающиеся на стенде; расширение стенда требует пересборки описания и типов.

## Ограничение v1

v1 умеет одно решение: приоритет партии. Остальные типы получат отказ со списком допустимых.
