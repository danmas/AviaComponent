## Why

Визуализация «как игра» требует не описания экрана, а воспроизводимого следа прогона.

Сейчас из прогона можно получить срезы на границах смен и итоговый отчёт. Этого достаточно для проверки правил, но недостаточно, чтобы внешний агент (или новый UI) показал:

- как заявка появляется на входе;
- как она превращается в партии;
- как детали идут от участка к участку;
- где и сколько они лежат в очередях.

Без следа агент будет угадывать тайминг. С следом он получает готовый сценарий и может предлагать варианты интерфейса, не трогая ядро.

## What Changes

- Появляется **след прогона** — упорядоченная по времени последовательность наблюдаемых событий и кадров.
- След пишется существующим прогоном (`runStand`) и не меняет правила цеха.
- Один seed + уровень + помеха + решения дают один и тот же след.
- След пригоден для проигрывания по времени (анимация, внешний агент, отладка).
- Два канала доставки одного формата: **файл JSON** (для внешнего агента и сохранения игры) и **`GET /v1/sessions/:id/trace`** (для UI игры). Это единственный новый маршрут, и он появляется вместе со следом.

Не меняется:

- Правила производства, ёмкости, садка, частичное закрытие.
- Остальные маршруты контракта `/v1`: след не встраивается в существующие ответы и не меняет их форму.
- Существующие эталоны прогонов.

## Impact

| Файл / каталог | Воздействие |
|----------------|-------------|
| `SIM/run/` | сборка следа из уже существующих событий и срезов |
| `SIM/api/server.ts` | новый маршрут `GET /v1/sessions/:id/trace`, схема пересобирается |
| `SIM/api-client/` | метод получения следа, типы пересобираются |
| `SIM/test/fixtures/` | один эталонный след |
| `openspec/changes/sim-game-recording/` | эта спека |
| внешний агент / новый UI | потребитель следа |
