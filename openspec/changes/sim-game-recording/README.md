# Изменение: след прогона для игровой визуализации

**Этап:** после `sim-ui-review`.
**Зависимости:** движок смен (пролёживание, частичное закрытие, садка), API-контракт `/v1`, решения руководителя.

## Зачем

Чтобы сделать визуализацию движения заявок и партий более игровой и отдать её внешнему агенту, нужен **воспроизводимый след**, а не только итоговый отчёт.

Сейчас из прогона можно получить срезы на границах смен и итоговый отчёт. Этого достаточно для проверки правил, но недостаточно, чтобы показать:

- как заявка появляется на входе;
- как она превращается в партии;
- как детали идут от участка к участку;
- где и сколько они лежат в очередях.

Без следа агент будет угадывать тайминг. Со следом он получает готовый сценарий и может предлагать варианты интерфейса, не трогая ядро.

## Что в следе

| Часть | Содержание |
|---|---|
| Шапка `meta` | seed, уровень, помеха, горизонт, длина смены |
| События | шесть типов: `order-registered`, `batch-appeared`, `operation-ready`, `operation-started`, `operation-completed`, `decision-applied` |
| Кадры | по одному на границу смены: показатели с покрытием и положение партий с ожиданием |

Формат описан в `design.md` D6 с примером каждого события. Эталон формы — `docs/TRACE-EXAMPLE.json`.

## Замер объёма

Прогон `clean`/`incoming`, seed 42, 12 смен: **155 событий**, 12 кадров, **≈ 22 КБ**. Это тот же порядок, что текущий отчёт (12 КБ), — файл читается целиком, дробить не нужно.

## Чего нет

- Анимации.
- Изменения правил цеха.
- Полного `PlantState` в кадрах: кадр — точка сверки, а не второй срез цеха.
- Замены среза цеха для разбора: вердикт по кадру не посчитать, в нём нет `done` и `readyAt`.

## Два канала, один формат

- **Файл JSON** — внешнему агенту и для сохранения игры. Самодостаточен, читается без сервера.
- **`GET /v1/sessions/:id/trace`** — UI игры. Отдаёт то же самое.

Совпадение форматов проверяется тестом: файл и ответ API должны быть побайтово равны.

## Обратная совместимость

След пишется, только если его попросили. Обычный прогон не меняется, эталоны не пересобираются. Проверяется тестом побайтового совпадения на четырёх уровнях.
