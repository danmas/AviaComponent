## ADDED Requirements

### Requirement: След прогона детерминирован

Один и тот же seed, уровень, помеха и список решений SHALL давать один и тот же след.

#### Scenario: Повторный прогон даёт тот же след

- **WHEN** два прогона запущены с одинаковыми параметрами
- **THEN** их следы совпадают

#### Scenario: Другой seed даёт другой след

- **WHEN** seed изменён
- **THEN** след отличается

### Requirement: След содержит события на каждое значимое изменение

След MUST фиксировать появление заявок, рождение партий, готовность операций, взятие ресурсом, закрытие и решения руководителя.

#### Scenario: Заявка зарегистрирована

- **WHEN** заявка входит в систему
- **THEN** в следе есть событие с моментом поступления

#### Scenario: Партия создана

- **WHEN** партия появляется в цехе
- **THEN** в следе есть событие с `appearedAt` и ссылкой на заявку

#### Scenario: Операция стала готовой

- **WHEN** открылись все ворота операции
- **THEN** в следе есть момент `readyAt`

#### Scenario: Ресурс взял операцию

- **WHEN** ресурс начал операцию
- **THEN** в следе есть момент `startedAt` и участок

#### Scenario: Операция закрыта

- **WHEN** операция закрыта (полностью или частично)
- **THEN** в следе есть событие с количеством сделанного и годного

#### Scenario: Решение применено

- **WHEN** руководитель применил решение
- **THEN** в следе есть событие с `appliedAt`

### Requirement: По последовательности событий восстанавливается движение

Для каждой партии по следу MUST быть возможно восстановить порядок участков и ожидание между ними без явных стрелок from→to.

#### Scenario: Пролёживание вычисляется

- **WHEN** у операции есть `readyAt` и `startedAt`
- **THEN** ожидание равно их разнице

#### Scenario: Переход на следующий участок виден

- **WHEN** операция закрыта и следующая стала готовой
- **THEN** по двум событиям видно, что партия перешла дальше

### Requirement: Опорные кадры на границах смен

След SHALL содержать кадр на каждую границу смены.

#### Scenario: Кадр содержит свод и краткий цех

- **WHEN** наступила граница смены
- **THEN** кадр включает показатели с покрытием и положение партий

#### Scenario: Кадр не содержит сырого состояния

- **WHEN** формируется кадр
- **THEN** в него не входит полный `PlantState`

### Requirement: След доступен файлом и через API

Один и тот же формат следа MUST отдаваться файлом и методом API.

#### Scenario: Файл для внешнего агента

- **WHEN** прогон сохранён в файл
- **THEN** файл является самодостаточным JSON и читается без сервера

#### Scenario: API для UI игры

- **WHEN** клиент запрашивает `GET /v1/sessions/:id/trace`
- **THEN** ответ имеет тот же формат, что и файл

#### Scenario: Форматы совпадают

- **WHEN** один и тот же прогон сохранён в файл и запрошен через API
- **THEN** содержимое совпадает

### Requirement: Прошлое не переписывается

Решение, применённое на смене N, MUST NOT изменять события и кадры до этого момента.

#### Scenario: Решение не трогает ранние кадры

- **WHEN** ранг применён на смене 5
- **THEN** кадры и события до смены 5 остаются прежними

### Requirement: Формат следа зафиксирован

След SHALL содержать шапку `meta` с seed, уровнем, помехой, горизонтом и длиной смены, список событий и список кадров. События MUST быть упорядочены по минуте.

#### Scenario: Шапка описывает прогон

- **WHEN** след сформирован
- **THEN** в шапке `meta` есть seed, уровень, помеха, горизонт и длина смены

#### Scenario: События упорядочены

- **WHEN** след прочитан
- **THEN** минуты событий не убывают

#### Scenario: Шесть типов событий

- **WHEN** след содержит события
- **THEN** каждый тип — один из шести: `order-registered`, `batch-appeared`, `operation-ready`, `operation-started`, `operation-completed`, `decision-applied`

#### Scenario: Форма совпадает с эталонным примером

- **WHEN** след сформирован
- **THEN** набор полей каждого события и кадра совпадает с `docs/TRACE-EXAMPLE.json`, расхождение — дефект

### Requirement: Объём следа измеряется

След SHALL иметь измеренный объём, зафиксированный в документации. Реализация MUST NOT увеличивать объём сверх записанного без объяснения.

#### Scenario: Объём эталонного прогона

- **WHEN** прогон `clean`/`incoming`, seed 42, горизонт 12 смен сохранён в след
- **THEN** объём близок к 22 КБ, а число событий — к 155

#### Scenario: Кадр не содержит сырого состояния

- **WHEN** сформирован кадр смены
- **THEN** в нём нет плановых и сделанных штук, моментов готовности и старта

### Requirement: След не заменяет срез цеха

Кадр следа SHALL быть краткой точкой сверки. Он MUST NOT использоваться как источник для вердикта разбора.

#### Scenario: Вердикт по кадру не считается

- **WHEN** разбор строит вердикт
- **THEN** он берёт срез цеха, а не кадр следа, потому что в кадре нет сделанного и моментов готовности

#### Scenario: Срез цеха по-прежнему запрашивается разбором

- **WHEN** открыт разбор смены
- **THEN** запрос среза цеха выполняется, несмотря на наличие кадров в следе
