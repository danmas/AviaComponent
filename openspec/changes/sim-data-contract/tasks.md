# Задачи этапа 1: контракт данных

## Контроль до работы

- [ ] Проверить, что `openspec validate sim-data-contract --strict` проходит до начала правок
- [ ] Зафиксировать параметры первой версии (масштаб, смена, горизонт) в `README_SIM_DATA.md` и после этого не менять
- [ ] Свериться с `SIM/README_Game_v1.md`: состав четырёх показателей и пяти блоков совпадает

## Модель данных

- [ ] `SIM/contract/types.ts` — сущности мира предприятия
- [ ] `SIM/contract/types.ts` — сущности мира Системы, отдельными типами
- [ ] `SIM/contract/units.ts` — типы единиц: н/ч, станко-часы, человеко-часы, печь-часы, сутки садки
- [ ] `SIM/contract/units.ts` — явная функция перевода с обязательным основанием
- [ ] Проверка: попытка сложить разнородные единицы падает на типах

## Контракт событий

- [ ] `SIM/contract/slices.ts` — три среза: цех (реальность), записи ролей, свод
- [ ] `SIM/contract/events.ts` — события предприятия в Систему: назначение, факт, брак, приход материала
- [ ] `SIM/contract/events.ts` — события Системы в предприятие: план, сменное задание
- [ ] Девять потоков ввода по ролям, у каждого свой тип события
- [ ] Оба времени у факта: истинное и время записи
- [ ] Отсутствие поля «пропущено» — пропуск выражается отсутствием события
- [ ] `SIM/contract/version.ts` — номер версии и правило чтения старых событий

## Наблюдаемое состояние цеха

- [ ] `SIM/contract/plant-state.ts` — участки, станки, партии, простои как отдельный срез
- [ ] Срез доступен экрану цеха и разбору, но не расчёту показателей

## Формулы показателей

- [ ] `SIM/contract/metrics.ts` — портфель заявок, с перечнем читаемых записей
- [ ] `SIM/contract/metrics.ts` — перегрузка участков, с перечнем читаемых записей
- [ ] `SIM/contract/metrics.ts` — принято за смену, по времени записи
- [ ] `SIM/contract/metrics.ts` — риск сроков, расчётная дата против договорной
- [ ] Каждая формула сопровождается перечнем записей и не читает скрытое состояние

## Журнал решений

- [ ] `SIM/contract/journal.ts` — формат записи: момент, действие, показатель-основание, покрытие, последствие
- [ ] Формат разбора: «подтвердилось / разошлось / невозможно проверить», без баллов

## Проверки

- [ ] Правило линтера: модуль Системы не импортирует модуль предприятия
- [ ] Правило: расчёт показателей не читает срез состояния цеха
- [ ] Тест: подмена скрытого состояния не меняет ни один из четырёх показателей
- [ ] Тест: экран цеха видит операцию, которую не отметили в Системе
- [ ] Тест: два прогона с одним seed совпадают побайтово
- [ ] Тест: событие версии 1 читается после введения версии 2

## Заметка и документирование

- [ ] `SIM/README_SIM_DATA.md` — модель данных, контракт, формулы, параметры первой версии
- [ ] `CHANGELOG.md` — версия PATCH, раздел «Добавлено»
- [ ] `KB/README_INDEX.md` — ссылка на `SIM/README_SIM_DATA.md`
- [ ] `openspec validate --all --strict` — без падений

## Если что-то не сходится

- [ ] Если показатель не собирается без истины — записать это как отдельный результат, а не обходить
- [ ] Если контракт требует поля, которого нет в документах — помечать как гипотезу, не как факт
- [ ] Если параметры пришлось менять после прогона — зафиксировать причину в `design.md`
