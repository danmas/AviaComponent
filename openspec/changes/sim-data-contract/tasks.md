# Задачи этапа 1: контракт данных

## Контроль до работы

- [x] Проверить, что `openspec validate sim-data-contract --strict` проходит до начала правок
- [x] Зафиксировать параметры первой версии (масштаб, смена, горизонт) в `README_SIM_DATA.md` и после этого не менять
- [x] Свериться с `SIM/README_Game_v1.md`: состав четырёх показателей и пяти блоков совпадает

## Модель данных

- [x] `SIM/contract/types.ts` — сущности мира предприятия
- [x] `SIM/contract/types.ts` — сущности мира Системы, отдельными типами
- [x] `SIM/contract/units.ts` — типы единиц: н/ч, станко-часы, человеко-часы, печь-часы, сутки садки
- [x] `SIM/contract/units.ts` — явная функция перевода с обязательным основанием
- [x] Проверка: попытка сложить разнородные единицы падает на типах

## Контракт событий

- [x] `SIM/contract/slices.ts` — три среза: цех (реальность), записи ролей, свод
- [x] `SIM/contract/events.ts` — события предприятия в Систему: назначение, факт, брак, приход материала
- [x] `SIM/contract/events.ts` — события Системы в предприятие: план, сменное задание
- [x] Девять потоков ввода по ролям, у каждого свой тип события
- [x] Оба времени у факта: истинное и время записи
- [x] Отсутствие поля «пропущено» — пропуск выражается отсутствием события
- [x] `SIM/contract/version.ts` — номер версии и правило чтения старых событий

## Наблюдаемое состояние цеха

- [x] `SIM/contract/plant-state.ts` — участки, станки, партии, простои как отдельный срез
- [x] Срез доступен экрану цеха и разбору, но не расчёту показателей

## Формулы показателей

- [x] `SIM/contract/metrics.ts` — портфель заявок, с перечнем читаемых записей
- [x] `SIM/contract/metrics.ts` — перегрузка участков, с перечнем читаемых записей
- [x] `SIM/contract/metrics.ts` — принято за смену, по времени записи
- [x] `SIM/contract/metrics.ts` — риск сроков, расчётная дата против договорной
- [x] Каждая формула сопровождается перечнем записей и не читает скрытое состояние

## Журнал решений

- [x] `SIM/contract/journal.ts` — формат записи: момент, действие, показатель-основание, покрытие, последствие
- [x] Формат разбора: «подтвердилось / разошлось / невозможно проверить», без баллов

## Проверки

- [x] Правило линтера: модуль Системы не импортирует модуль предприятия
- [x] Правило: расчёт показателей не читает срез состояния цеха
- [x] Тест: подмена скрытого состояния не меняет ни один из четырёх показателей
- [x] Тест: экран цеха видит операцию, которую не отметили в Системе
- [x] Тест: два прогона с одним seed совпадают побайтово
- [x] Тест: событие версии 1 читается после введения версии 2

## Если что-то не сходится

- [x] Если показатель не собирается без истины — записать это как отдельный результат, а не обходить
- [x] Если контракт требует поля, которого нет в документах — помечать как гипотезу, не как факт
- [ ] Если параметры пришлось менять после прогона — зафиксировать причину в `design.md`
