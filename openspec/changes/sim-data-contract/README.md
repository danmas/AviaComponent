# Изменение: контракт данных игровой модели

**Этап:** 1 из 5.
**Спецификация игры:** [SIM/README_Game_v1.md](../../../SIM/README_Game_v1.md)

## Карта файлов

| Файл | Содержание |
|------|-----------|
| `proposal.md` | Зачем контракт, что меняется, на что влияет |
| `design.md` | Решения D1–D10 с обоснованием, риски |
| `specs/sim-core/spec.md` | Требования к модели данных и контракту событий |
| `tasks.md` | Чекбоксы: контроль → схема → контракт → проверка → заметка |

## Этапы

| Этап | Изменение | Содержание | Зависит от |
|------|-----------|------------|------------|
| **1** | `sim-data-contract` | модель данных, контракт событий, формулы показателей, журнал решений | — |
| **2** | `sim-plant-engine` | headless движок цеха: участки, станки, операции, партии, брак, простои | 1 |
| **3** | `sim-system-model` | модель Системы: заявки, ТП, нормы, план версиями, отметки, ОТК | 1, 2 |
| **4** | `sim-screens` | три слоя экранов: цех, рабочие места ролей, главный экран руководителя | 1–3 |
| **5** | `sim-run-report` | прогон партии и разбор: сопоставление решений с фактом | 2–4 |

Этапы 2 и 3 можно вести параллельно после 1: движку цеха не нужна Система, модели Системы нужен контракт, а не живой движок.
