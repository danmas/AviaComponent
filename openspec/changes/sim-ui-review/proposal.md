## Why

Свод даёт руководителю записи и цену решения. Но **проверить, был ли он прав, негде**. Журнал фиксирует, на каком основании решено; факт того, что из этого вышло, нигде не сопоставляется.

Это последний из трёх слоёв `sim-ui` и единственное место, где игрок видит **цех**: экран свода показывает записи, разбор — что было на самом деле. Без него игрок не узнаёт, ошибочны ли его записи, и тренажёр не замыкается.

Главная механика, ради которой всё делалось: **управленческая асимметрия**. Руководитель решает по записям, правда доступна только в разборе. Если цех виден всегда, проверять нечего; если не виден никогда, учиться не на чем.

### Что уже есть (проверено)

| Что нужно | Где | Состояние |
|---|---|---|
| Записи решений | `decisionJournal` сессии | `at`, `action`, `basisMetric`, `basisValue`, `coverage`, `consequence` |
| Вердикты | `system/journal.ts` | `ReviewLine`, `review()`, три вердикта — **тип есть, расчёт не подключён** |
| Прошлые срезы свода | `GET /sessions/:id?shift=N` | 200, покрытие восстановимо (`portfolio` 1 → 0.8) |
| Прошлые срезы цеха | `GET /sessions/:id/shop?shift=N` | 200, 42 операции |
| Сроки заказов | срез ролей | `contractDue` у каждого заказа |
| Факт по партии | срез цеха | `status`, `readyAt`, `startedAt`, `done` |

Проверено: срезы за прошлые смены читаются и не переписываются. Значит разбор можно строить **без нового контракта** — из того, что уже отдаётся.

## What Changes

- Появляется **экран разбора**: по каждому решению смены — что было записано, что было в цехе, вердикт.
- Подключается расчёт вердикта, который уже описан в ядре, но не используется: **подтвердилось / разошлось / невозможно проверить**.
- Появляется **сопоставление по заказу**: договорный срок против факта закрытия.
- Разбор запрашивает срез цеха — единственное место, где это разрешено.

## Ключевое ограничение, которое надо удержать

**Разбор не оценивает поступок.** Он показывает: записи, на которых решено, факт, который вышел, и является ли факт следствием решения. Балла, рейтинга, «правильно/неправильно» нет — это прямо запрещено в `sim-ui` D5 и повторено в `sim-ui-dashboard` D5.

## Impact

| Файл | Воздействие |
|------|-------------|
| `SIM/system/journal.ts` | расчёт вердикта по факту, а не только тип |
| `SIM/ui/src/screens/ReviewScreen.tsx` | экран разбора |
| `SIM/ui/src/lib/review.ts` | сборка строк разбора из журнала и срезов |
| `SIM/ui/src/App.tsx` | третья закладка |
| `SIM/ui/test/` | тесты вердиктов |
| `SIM/api/*`, `api-client` | **не меняются**, если вердикт считается на клиенте |

## Чего это изменение не делает

- Рабочие места ролей (этап 5 исчерпан, отдельное направление).
- Оценка и рейтинг решений.
- Автоматическое улучшение решений: разбор показывает, но не советует.
- Изменение правил цеха.
