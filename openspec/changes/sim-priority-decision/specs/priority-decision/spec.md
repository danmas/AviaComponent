## Purpose

Одно решение руководителя — смена приоритета партии — действует от момента применения вперёд, пишется в журнал с основанием, и даёт срез четырёх показателей на границу смены.

## ADDED Requirements

### Requirement: Решение действует вперёд и не переписывает прошлое

Приоритет партии SHALL применяться только с момента решения. Порядок очереди до этого момента MUST остаться прежним.

#### Scenario: Прошлое не меняется

- **WHEN** решение о смене приоритета принято на границе 5-й смены и прогон повторён с этим решением
- **THEN** закрытия операций до этой границы совпадают с прогоном без решения — момент и идентификатор каждой операции

#### Scenario: Будущее меняется

- **WHEN** партия получает ранг выше остальных на границе 5-й смены
- **THEN** начиная с этой границы её операции стартуют раньше, чем в прогоне без решения

#### Scenario: Начатая работа не отменяется

- **WHEN** решение принято в момент, когда операция партии уже в статусе «выполняется»
- **THEN** эта операция доводится до конца, и отрыва после старта не происходит

#### Scenario: Смена приоритета не ускоряет ресурс

- **WHEN** партия с наивысшим рангом ждёт освобождения единственного ресурса участка
- **THEN** она стартует не раньше, чем ресурс освободится, — решение меняет порядок очереди, но не мощность участка

### Requirement: Решение не подменяет договорную дату

Ранг приоритета SHALL быть отдельным полем, не изменяющим договорную дату заявки. Показатель «риск сроков» MUST продолжать сравнивать расчётную дату с договорной.

#### Scenario: Показатель не улучшается самим решением

- **WHEN** решение повышает приоритет партии заявки без договорной даты
- **THEN** эта заявка остаётся в числе неоценённых, и покрытие показателя не растёт

#### Scenario: Договорная дата неизменна

- **WHEN** прогон выполнен с решениями и без них
- **THEN** значение договорной даты каждой заявки в записях совпадает

### Requirement: Срез показателей считается на границу смены

Срез на смену N SHALL считаться прогоном с горизонтом N+1. Срез MUST NOT собираться из прогона с большим горизонтом.

#### Scenario: Снимок загрузки относится к нужной смене

- **WHEN** срез считается для смены N
- **THEN** `areaLoads` берётся из прогона с горизонтом N+1, где она описывает именно смену N

#### Scenario: Срез нельзя взять из полного прогона

- **WHEN** сравнивается `areaLoads` прогона с горизонтом 12 и прогона с горизонтом N+1 при N меньше 11
- **THEN** значения различаются, потому что в полном прогоне `areaLoads` описывает последнюю смену горизонта

#### Scenario: Закрытия на префиксе устойчивы

- **WHEN** сравниваются прогоны с горизонтами N+1 и 12 при одинаковых seed, уровне, помехе и решениях
- **THEN** закрытия операций до минуты начала смены N совпадают

### Requirement: Срез не читается из журнала решений

Срез SHALL считаться из записей прогона. Список решений MUST NOT использоваться как основание для значений показателей сверх того, что они изменили в цехе.

#### Scenario: Срез без решений на прежних границах

- **WHEN** сессия продвинута на две смены без единого решения
- **THEN** срезы совпадают со срезами того же прогона без списка решений

#### Scenario: Основание показателя — запись, не решение

- **WHEN** решение о приоритете применено, но ни одна операция из-за него не стартовала в эту смену
- **THEN** показатель «принято за смену» не меняется, потому что фактов в записях не прибавилось

### Requirement: Решение пишется в журнал с основанием

Применённое решение SHALL попадать в журнал разбора с моментом, действием, показателем-основанием, его значением, покрытием и последствием.

#### Scenario: Запись содержит основание

- **WHEN** решение применено на смене с известным покрытием показателя «риск сроков»
- **THEN** в журнале есть запись с этим покрытием и значением показателя на момент решения

#### Scenario: Покрытие в допустимом диапазоне

- **WHEN** решение записывается в журнал
- **THEN** покрытие лежит в полуинтервале от нуля до единицы, и запись не создаётся при пустом действии

### Requirement: Прогон остаётся детерминированным с решениями

Прогон SHALL возвращать одинаковый отчёт при одинаковых seed, уровне, помехе и списке решений.

#### Scenario: Повтор с решениями

- **WHEN** прогон с непустым списком решений запускается дважды
- **THEN** тексты отчётов совпадают

#### Scenario: Пустой список решений

- **WHEN** прогон запускается без решений
- **THEN** отчёт совпадает с отчётом до этого изменения — побайтово, включая сохранённые фикстуры
