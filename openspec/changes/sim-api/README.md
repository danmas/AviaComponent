# Изменение: API симулятора

**Этап:** 3 из 5 (подэтапы 3a–3c). Зависит от `sim-priority-decision`.
**Спецификация игры:** [SIM/README_Game_v1.md](../../../SIM/README_Game_v1.md)

## Что это меняет в исходном черновике ТЗ

Черновик исходил из того, что «слой только оркестрирует `run/run.ts`» и что `currentShift` — самостоятельное состояние. Проверка кода это опровергла; правки внесены в `design.md`, здесь — сводка.

| Пункт черновика | Как на самом деле | Что сделано |
|---|---|---|
| «слой оркестрирует `run.ts`» | `runStand` проходит весь горизонт за вызов, точки останова нет | шаг смены = перепрогон с горизонтом `N+1` (D1) |
| Сессия хранит `PlantState` | тогда два источника истины рядом с `runStand` | сессия хранит только параметры, решения и журнал выданного (D2) |
| `horizonShifts` — свободный параметр | в ядре это константа `CONTRACT_STAND`, читается в 7 местах, охраняется 10–15 | горизонт становится аргументом (этап 2.5), диапазон ограничен стендом (D3) |
| `GET /metrics` отдаёт срез | `areaLoads` перезаписывается каждую смену, срез из финальных записей не выводится | срез перепрогоном (D1, этап 2.5 D3) |
| Мощность участка | `capacityOf` зашивает 12 ч / 0.5 суток в `run.ts:129`, это не параметр стенда | сервер берёт `capacity` из `AreaLoadRecord` как есть (D3a) |
| Решения любого типа | в ядре нет ни одного из восьми решений | v1 умеет одно — приоритет (этап 2.5) |
| Три среза — «предложение» | `LAYERS` и `ShopSlice` уже в контракте этапа 1 | срезы отдаются по готовым типам (D4) |
| «ядро не знает про HTTP» | `boundary.ts` не знает зону `api` и пропускает импорт из `plant/` в `api/` молча | зона `api` добавлена в проверку границы |
| Порт не указан | 3000–3002, 3006, 3010 заняты | 3400 с проверкой занятости (D8) |

## Замеры, определившие этап

| Замер | Значение |
|-------|----------|
| Полный прогон 12 смен | 0.7–1.2 мс |
| Прогон 120 смен | 14.7 мс |
| Префикс 0–5 смен при горизонте 6 против 12 | совпал |
| Пошаговый прогон (1…12) против полного | расхождений нет |
| `PlantState` в JSON | 11.9 КБ |

Пошаговый режим ядру не нужен: перепрогон с отсечкой даёт тот же результат за 1 мс.
