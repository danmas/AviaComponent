## Purpose

Контракт HTTP и WebSocket над ядром симулятора для нескольких клиентов: версия API, машинно-читаемое описание, генерируемые клиентские типы, полный реестр событий потока. Сервер не содержит правил модели и не знает про экраны.

## ADDED Requirements

### Requirement: Версия API в пути

HTTP-контракт SHALL версионироваться префиксом пути `/v1/`. Обращение к неизвестной версии MUST отвечать `404` с перечислением поддерживаемых версий.

#### Scenario: Маршрут версии 1 работает

- **WHEN** клиент обращается к `POST /v1/sessions` с корректным телом
- **THEN** сервер создаёт сессию и отвечает `201` с полем `apiVersion: 'v1'`

#### Scenario: Неизвестная версия отвергается

- **WHEN** клиент обращается к `POST /v2/sessions`
- **THEN** сервер отвечает `404` с телом `{ error: 'unknown-api-version', supported: ['v1'] }` и сессию не создаёт

#### Scenario: Версия отличается от «тело плохое»

- **WHEN** клиент обращается к `/v2/sessions`
- **THEN** код ответа `404`, а не `400`, потому что запрос адресован несуществующей версии, а не содержит ошибку в теле

### Requirement: Версия в теле ответа

Каждый успешный ответ SHALL содержать поле `apiVersion` на верхнем уровне. Поле MUST присутствовать и в ответах с ошибкой.

#### Scenario: Версия в срезе

- **WHEN** клиент получает срез свода на текущую смену
- **THEN** в теле есть `apiVersion: 'v1'` рядом с `layer: 'summary'`

#### Scenario: Версия в отказе

- **WHEN** сервер отказывает в решении с моментом в прошлом
- **THEN** тело отказа содержит `apiVersion: 'v1'` и код ошибки

### Requirement: Машинно-читаемое описание из типов ядра

Описание `SIM/api/openapi.json` SHALL генерироваться из типов `SIM/contract/` и `SIM/system/`. Ручная правка MUST NOT быть источником изменения формы ответа.

#### Scenario: Описание помечено как сгенерированное

- **WHEN** файл `SIM/api/openapi.json` открыт
- **THEN** он содержит признак `x-generated: true` и команду сборки

#### Scenario: Изменение типа меняет описание

- **WHEN** в типе, попадающем в ответ, добавлено или переименовано поле
- **THEN** `npm run openapi` меняет `openapi.json`, а тест сверки падает, если описание не пересобрано

#### Scenario: Ручная правка обнаруживается

- **WHEN** `openapi.json` изменён вручную без изменения типов
- **THEN** тест сверки описания с сервером падает на расхождении

### Requirement: Описание совпадает с фактическими ответами

Схемы ответов в `openapi.json` SHALL совпадать с тем, что сервер отдаёт на фиксированном прогоне. Расхождение MUST считаться ошибкой сборки.

#### Scenario: Схема свода сверяется

- **WHEN** сервер отдаёт `GET /v1/sessions/:id` на стенде `clean`/`none` с seed 42
- **THEN** набор полей ответа совпадает с набором полей схемы `SummaryResponse` в `openapi.json`

#### Scenario: Лишнее поле — расхождение

- **WHEN** сервер начал отдавать поле, которого нет в схеме
- **THEN** тест сверки падает и называет поле

### Requirement: Клиентские типы генерируются

Пакет `SIM/api-client/` SHALL содержать типы, выведенные из `openapi.json`. Клиентский пакет MUST NOT импортировать серверные модули и библиотеки транспорта.

#### Scenario: Клиент не тянет сервер

- **WHEN** клиентский пакет импортирует `fastify` или модуль из `SIM/api/`
- **THEN** проверка границы завершается с кодом 1 и называет нарушителя

#### Scenario: Транспорт передаётся снаружи

- **WHEN** клиент создан функцией `createClient(baseUrl)` без явного транспорта
- **THEN** используется `fetch` среды, и в среде с `fetch` клиент работает без дополнительных зависимостей

#### Scenario: Клиент работает в Node

- **WHEN** клиент используется в тесте под Node без браузерных глобальных объектов
- **THEN** запрос среза свода выполняется успешно

### Requirement: Полный реестр событий потока

Протокол WebSocket SHALL перечислять все типы событий закрытым списком: `shift-started`, `shift-completed`, `metrics-updated`, `decision-applied`, `session-finished`.

#### Scenario: Известный тип обрабатывается

- **WHEN** клиент получает событие `shift-completed`
- **THEN** оно содержит `seq`, `at`, `type` и `payload` с номером закрытой смены

#### Scenario: Неизвестный тип не ломает клиент

- **WHEN** сервер прислал тип, которого нет в закрытом списке версии `v1`
- **THEN** клиент обязан его проигнорировать и продолжить чтение потока

#### Scenario: Номера не повторяются

- **WHEN** клиент продвигает две смены подряд
- **THEN** `seq` событий второй смены строго больше `seq` событий первой, повторов нет

### Requirement: Журнал потока ограничен окном

Журнал событий сессии SHALL хранить последние 200 записей. Запрос воспроизведения с номером вне окна MUST отвечать отказом с указанием самого старого доступного номера.

#### Scenario: Восстановление внутри окна

- **WHEN** клиент переподключается с `lastSeq` внутри окна
- **THEN** он получает все события с номерами больше `lastSeq` и ни одного повторно

#### Scenario: Номер вне окна

- **WHEN** клиент переподключается с `lastSeq`, который старше самого старого хранимого события
- **THEN** сервер отвечает `{ error: 'journal-window-exceeded', oldestSeq }` и клиент перечитывает срез с нуля

#### Scenario: Окно не растёт бесконечно

- **WHEN** в сессии накопилось больше 200 событий
- **THEN** самых старых в журнале нет, а размер журнала не превышает 200 записей

### Requirement: Срез цеха не попадает в свод

Ответ свода SHALL содержать только показатели. Поля состояния цеха MUST отсутствовать в своде и отдаваться отдельным маршрутом.

#### Scenario: Свод без цеха

- **WHEN** клиент запрашивает `GET /v1/sessions/:id`
- **THEN** в теле нет ключей `operations`, `downtimes`, `resources`, `batches`

#### Scenario: Цех отдельным маршрутом

- **WHEN** клиент запрашивает `GET /v1/sessions/:id/shop`
- **THEN** в теле есть `layer: 'shop'` и состояние операций и простоев

#### Scenario: Цех тяжелее свода

- **WHEN** сервер отдаёт свод и цех на одной и той же смене
- **THEN** тело свода не превышает 2 КБ, тело цеха — не менее 8 КБ на стенде seed 42

### Requirement: CORS явным списком источников

Сервер SHALL принимать источники из конфигурации и MUST NOT принимать `*` при включённом CORS.

#### Scenario: Разрешённый источник

- **WHEN** клиент с источником из списка `SIM_API_ORIGINS` делает запрос
- **THEN** ответ содержит `Access-Control-Allow-Origin` с этим источником

#### Scenario: Неизвестный источник

- **WHEN** клиент с источником не из списка делает запрос
- **THEN** сервер не выдаёт разрешающий заголовок

#### Scenario: Звёздочка отвергается при старте

- **WHEN** конфигурация содержит `*` в `SIM_API_ORIGINS`
- **THEN** сервер завершается с сообщением, что `*` не допускается, и кодом возврата 1

### Requirement: Серверный код без enum

Модули `SIM/api/` SHALL использовать `interface`, `type` и `as const`. Конструкция `enum` MUST NOT встречаться в серверной зоне.

#### Scenario: Enum в сервере обнаруживается

- **WHEN** в файле зоны `api` встречается `enum`
- **THEN** проверка границы завершается с кодом 1 и называет файл

#### Scenario: Ядро не правится ради запуска

- **WHEN** сервер запускается командой `npm run api` на Node без флага сборки
- **THEN** запуск проходит без шага компиляции TypeScript
