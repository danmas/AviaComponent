# Изменение: главный экран руководителя

**Этап:** 4 из 5. Зависит от `sim-api-contract`.
**Спецификация игры:** [SIM/README_Game_v1.md](../../../SIM/README_Game_v1.md)

## Что это изменение решает

Данные для честного экрана в контракте **уже есть** — покрытие у каждого числа, причина недоверия, несложимые единицы, происхождение записи. Задача UI не нарисовать красиво, а **не соврать**: показать предел знания так, чтобы это читалось до чтения подписи.

## Четыре замера, определившие язык

Стенд `clean`/`none`, seed 42, смена 0:

| Замер | Значение | Что определил |
|---|---|---|
| `acceptedShift.coverage` | **0.083** (3 из 36) | число с весом (D2) |
| `portfolio`/`overload`/`scheduleRisk`.coverage | 1.0 | покрытие у каждого своё (D3 спеки) |
| `queueByUnit` | три единицы отдельно | несложимые единицы (D4) |
| `decisionJournal[].coverage` | есть | цена до подтверждения (D7) |

Главное: **разное покрытие на одном экране — норма**. Показатель «принято за смену» на первой смене собран на трёх записях из тридцати шести, и это не сбой, а предмет игры.

## Что этот этап не делает

- **Рабочие места ролей** — этап 5.
- **Цех как отдельный экран** — только в разборе, отдельным изменением.
- **Остальные семь решений** руководителя.
- **Аутентификация, мультиплеер, сохранение прогресса.**

## Проверка D9 из `sim-api-contract`

Здесь проверяется главное обещание контракта: **если экран нельзя написать против сгенерированных типов — контракт плох, и это видно до вёрстки**.

При подготовке этой спеки проверка уже сработала: `decisions` и `decisionJournal` описывались как `unknown[]`, потому что на смене 0 они пусты. Генератор описания исправлен — теперь срез снимается и после решения. Это ровно тот случай, ради которого контракт писался до UI.
