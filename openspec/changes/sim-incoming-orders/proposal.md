## Why

Все заказы стенда регистрируются на **минуте 0** и запускаются в цех сразу:

```ts
for (const order of catalog) {          // четыре заказа
  accept({ type: 'order-registered', recordedAt: 0, ... });
  ...
  for (const batchId of order.batchIds) {
    shop = launchBatch(shop, { id: batchId, ... });   // все шесть партий в нулевой тик
  }
}
```

Портфель руководителя постоянен: он видит одни и те же четыре заказа весь прогон. Ни один заказ не приходит в середине — значит руководителю нечего решать про приоритеты между старым и новым, а тренажёр не проверяет главную ситуацию ПДО: **что делать, когда приходит срочное, а ресурсы заняты**.

В документах заказ приходит в систему через коммерсанта в течение периода планирования, а не единым пакетом на старте. Порядок поступления — часть предметной области.

### Что мешает просто «добавить заказ на ходу»

| Препятствие | Где | Почему мешает |
|---|---|---|
| `EXPECTED.orders = 4` | `run/levels.ts` | Знаменатель покрытия портфеля. Пятый заказ либо не учтётся, либо сломает «покрытие 1.0» на эталонах |
| Ожидания смен (`EXPECTED.marks = 36`) | `run/levels.ts` | Частичные отметки считаются от постоянного знаменателя |
| `dueByBatch` заполняется один раз | `run/run.ts` | Срок нового заказа некуда положить |
| `launchBatch` вызывается только до прогона | `run/run.ts` | В движке нет пути «создать партию в середине» |
| Контрактные события пишутся с `recordedAt: 0` | `run/run.ts` | Время регистрации — часть наблюдаемого факта, а сейчас константа |

## What Changes

- Заказ получает **момент поступления** — минуту, на которой он входит в систему. Для старых заказов это ноль.
- Партии заказа создаются в цехе в момент поступления, а не до прогона.
- Знаменатели покрытия перестают быть константами там, где зависят от числа заказов: считается по фактически поступившим на текущую смену.
- Появляется помеха «срочный заказ в середине» — новый заказ с коротким сроком на смене N.
- Экран цеха показывает, когда партия появилась, и отличает новые партии от стартовых.

## Чего это изменение не делает

- Привязка «деталь → станок», табель, допуски.
- Пересдача брака в производство.
- Отмена и перенос заказа клиентом.
- Изменение сроков по уже принятому заказу.
